# Contributing to Nashira

Thank you for helping improve Nashira. Read this guide before opening an issue or pull request.

## Where contributions are accepted

Focused contributions can be proposed for code, workflows, skills, specifications, tests and documentation. Maintainers decide whether a proposal fits the product, security model and release plan.

All project-owned content is distributed under Apache License 2.0. Contributions use the same license as their destination and require DCO sign-off. No separate Contributor License Agreement is required under the current model.

## Before submitting

1. Search existing issues and pull requests.
2. Keep one issue or pull request focused on one problem.
3. Describe the observed and expected behavior and include a minimal reproduction.
4. Add or update tests when behavior changes.
5. Do not include credentials, customer data, personal data or internal infrastructure details.
6. Report security vulnerabilities privately under [SECURITY.md](SECURITY.md).

## Provenance and intellectual property

By submitting content, you represent that you have the right to contribute it under the license that applies to its destination.

- Identify copied, adapted or generated material and its source.
- Preserve required third-party notices.
- Do not paste code or documentation whose license is unknown or incompatible.
- Disclose material use of generative AI in the pull request. The contributor remains responsible for review, correctness, provenance and license compatibility.
- Do not submit an employer's or client's work without documented authorization.

Every contributed commit must include a Developer Certificate of Origin sign-off:

```text
Signed-off-by: Full Name <email@example.com>
```

Use `git commit --signoff`. The DCO text is in [docs/legal/DCO.md](docs/legal/DCO.md).

## Pull requests

A pull request should include:

- purpose and scope;
- linked issue or decision, when applicable;
- tests performed and their results;
- security, migration and compatibility impact;
- third-party or generated-material disclosures;
- screenshots only when they contain no sensitive information.

Maintainers can require additional review, changes or rejection when provenance, security or product fit is unclear.
